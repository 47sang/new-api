# PRODUCT.md — 请求/响应日志查看功能

## 1. 解决的问题

当前 API 网关的日志系统（`logs` 表）只记录计费摘要信息（`content` 字段存的是计费描述字符串），不保存完整的请求体和响应体。当用户或管理员需要排查 API 调用问题时，只能看到计费元数据，无法还原实际的请求参数和上游返回内容。

## 2. 功能概述

在现有日志系统之上，增加一套**可选的**请求/响应完整内容记录与查看功能。开启后，每次 API 中继请求的原始请求 JSON 和上游返回的响应 JSON（非流式场景）会被保存到独立的 `request_response_logs` 表中，用户和管理员可以通过日志详情弹窗查看。

## 3. 用户行为

### 3.1 开启功能

管理员通过以下任一方式开启：

- **环境变量**：设置 `REQUEST_RESPONSE_LOG_ENABLED=true`，重启服务生效。
- **管理界面 Option 设置**：将 `RequestResponseLogEnabled` 设为 `true`，运行时生效。

### 3.2 查看请求/响应（管理员）

1. 进入「使用日志」页面。
2. 点击某条日志行的「详情」按钮，打开日志详情弹窗。
3. 弹窗顶部有两个标签页：「概览」和「请求/响应」。
4. 切换到「请求/响应」标签页，看到：
   - **状态码**：HTTP 状态码（绿色=成功，红色=失败）
   - **请求体**：原始请求 JSON，格式化展示，支持一键复制
   - **响应体**：原始响应 JSON，格式化展示，支持一键复制
   - **响应大小**：响应体字节大小（KB）
5. 若请求对应的数据不存在（功能未开启或流式响应），显示提示信息。
6. 若数据正在加载，显示加载状态。

### 3.3 查看请求/响应（普通用户）

行为与管理员一致，但**只能查看自己账号下的日志**的请求/响应详情。尝试查看他人日志时返回 403 禁止访问。

### 3.4 流式响应的处理

- 流式响应（SSE）和 WebSocket 连接**不记录响应体**。
- 前端显示「无响应体（流式响应）」提示。
- 请求体仍然会被记录（因为请求体在进入 relay 前就已经被 `BodyStorage` 捕获）。
- 状态码旁的标记显示 `(Streaming)` 标识。

### 3.5 数据保留与清理

- 默认保留 **7 天**，可通过环境变量 `REQUEST_RESPONSE_LOG_RETENTION_DAYS` 调整。
- 设为 `0` 表示永久保留，不自动清理。
- 清理任务每 24 小时执行一次，启动时也会执行一次。
- 清理日志会输出到系统日志。

## 4. 边缘情况

| 场景 | 行为 |
|---|---|
| 功能关闭时发出请求 | 不记录，日志详情弹窗中「请求/响应」标签页显示数据不存在 |
| 响应体超过 2MB | 截断至 2MB，末尾追加 `[truncated, exceeds 2MB limit]` 标记 |
| 请求无 `request_id` | 跳过记录（理论上不会发生，因为 request-id 中间件保证每次请求都有） |
| 数据库写入失败 | 静默记录错误到系统日志，不影响主请求链路 |
| 二进制响应（图片/音频/视频） | 不记录响应体，跳过录制 |
| 请求报错（上游 4xx/5xx） | 仍记录请求体和错误响应体（如果非流式） |

## 5. 不包含的范围

- 不做请求/响应内容的脱敏处理（原始存储）。
- 不提供全局搜索请求/响应内容的接口（只能通过日志 ID 精确查询）。
- 不记录 WebSocket（Realtime API）的消息内容。
- 不提供批量导出请求/响应的功能。

## 6. 成功标准

- [x] 开启功能后，通过 API 发出的请求能够记录请求体和响应体到独立表
- [x] 日志详情弹窗中「请求/响应」标签页能正确展示请求和响应内容
- [x] 普通用户无法查看其他用户的请求/响应数据
- [x] 流式响应和二进制响应不会被记录
- [x] 超过保留期的数据能被自动清理
- [x] 功能关闭时对现有系统零影响（零性能开销）
- [x] 数据库支持 SQLite / MySQL / PostgreSQL 三种引擎
