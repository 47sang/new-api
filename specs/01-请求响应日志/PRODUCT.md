# PRODUCT.md — 请求/响应日志查看功能

## 1. 解决的问题

当前 API 网关的日志系统（`logs` 表）只记录计费摘要信息（`content` 字段存的是计费描述字符串），不保存完整的请求体和响应体。当用户或管理员需要排查 API 调用问题时，只能看到计费元数据，无法还原实际的请求参数和上游返回内容。

## 2. 功能概述

在现有日志系统之上，增加一套**可选的**请求/响应完整内容记录与查看功能。开启后，每次 API 中继请求的原始请求体和上游返回的响应体会被保存到独立的 `request_response_logs` 表中——**流式（SSE）响应与非流式响应均完整记录**，每次请求最终只保留一行记录。用户和管理员可以通过日志详情弹窗查看。

**🔑 存储设计原则**：流式响应的分片只在内存中累积，**请求结束后一次性落库**（按 `request_id` UPSERT 覆盖）。不做分片级持久化，避免写放大；存储成本与内容大小线性相关（O(内容大小)），而非 O(n²)。

## 3. 用户行为

### 3.1 开关控制（默认开启）

功能**默认启用**。管理员可通过以下任一方式关闭或重新开启（运行时即时生效）：

- **管理界面**：「系统设置 → 运维 → 日志维护」中的「记录完整请求体和响应体」开关（保存走 Option API）。
- **环境变量**：设置 `REQUEST_RESPONSE_LOG_ENABLED=false` 关闭（默认 `true`），重启服务生效；重新设为 `true` 或删除该变量并重启可恢复开启。
- **Option API**：调用管理端选项接口（`PUT /api/option/`）修改 `RequestResponseLogEnabled`。

**⚠️ 优先级说明**：Option 表中保存过的值会覆盖环境变量默认值（与其他运营选项行为一致）。

### 3.2 查看请求/响应（管理员）

1. 进入「使用日志」页面。
2. 点击某条日志行的「详情」按钮，打开日志详情弹窗。
3. 弹窗顶部有两个标签页：「概览」和「请求/响应」。
4. 切换到「请求/响应」标签页，看到：
   - **状态码**：HTTP 状态码（绿色=成功，红色=失败）
   - **请求体**：原始请求 JSON，格式化展示，支持一键复制
   - **响应体**：原始响应内容，格式化展示，支持一键复制
   - **响应大小**：响应体字节大小（KB）
5. 若请求对应的数据不存在（功能未开启时发出），显示提示信息。
6. 若数据正在加载，显示加载状态。

### 3.3 查看请求/响应（普通用户）

行为与管理员一致，但**只能查看自己账号下的日志**的请求/响应详情。尝试查看他人日志时提示禁止访问。

### 3.4 流式响应的处理

- 流式响应（SSE）**完整记录**：保存原始 SSE 报文（含 `data:` 行与结束标记），标记 `is_stream=true`。
- 前端识别流式内容后，逐条提取 `data:` 载荷的 JSON 进行格式化展示。
- 流式响应正常结束 → `is_completed=true`；客户端中途断开 → `is_completed=false`（保存已收到的部分内容）。
- WebSocket（Realtime API）连接不记录。

### 3.5 二进制响应的处理

- 图片、音频、视频等二进制响应**不保存响应体**（存入文本列无调试价值且浪费空间），`is_completed=false`。
- 请求体仍会记录，方便还原调用参数。

### 3.6 数据保留与清理

- 默认保留 **7 天**，可通过环境变量 `REQUEST_RESPONSE_LOG_RETENTION_DAYS` 调整。
- 设为 `0` 表示永久保留，不自动清理。
- 清理按 `created_at` 日期滚动删除，每 24 小时执行一次（启动时也会执行一次）；清理任务常驻，运行时开启开关后无需重启即可生效。
- 不支持 ClickHouse 日志库（该库不迁移 `request_response_logs` 表，配置后功能自动禁用）。
- 清理日志会输出到系统日志。

## 4. 边缘情况

| 场景 | 行为 |
|---|---|
| 功能关闭时发出请求 | 不记录，日志详情弹窗中「请求/响应」标签页显示数据不存在 |
| 响应体大小 | **不截断**，完整保存（存储压力通过保留期滚动清理控制） |
| 请求无 `request_id` | 跳过记录（理论上不会发生，因为 request-id 中间件保证每次请求都有） |
| 数据库写入失败 | 静默记录错误到系统日志，不影响主请求链路 |
| 二进制响应（图片/音频/视频） | 不记录响应体，请求体照常记录 |
| 流式响应中途客户端断开 | 保存已累积的部分内容，`is_completed=false` |
| multipart 请求（文件上传） | 请求体保存占位符（二进制内容不落库），响应照常记录 |
| 请求报错（上游 4xx/5xx） | 仍记录请求体和错误响应体 |
| 同一 `request_id` 重复写入 | 按 `request_id` UPSERT 覆盖，始终只保留最新一条 |

## 5. 不包含的范围

- 不做请求/响应内容的脱敏处理（原始存储）。
- 不提供全局搜索请求/响应内容的接口（只能通过日志 ID 精确查询）。
- 不记录 WebSocket（Realtime API）的消息内容。
- 不提供批量导出请求/响应的功能。

## 6. 成功标准

- [x] 开启功能后，通过 API 发出的请求能够记录请求体和响应体到独立表
- [x] 日志详情弹窗中「请求/响应」标签页能正确展示请求和响应内容
- [x] 普通用户无法查看其他用户的请求/响应数据
- [x] 流式响应（SSE）完整记录，前端可解析展示
- [x] 每次请求最终只占一行记录（UPSERT），无重复存储
- [x] 响应体不截断
- [x] 超过保留期的数据能被自动清理
- [x] 功能关闭时对现有系统零影响（零性能开销）
- [x] 数据库支持 SQLite / MySQL / PostgreSQL 三种引擎
