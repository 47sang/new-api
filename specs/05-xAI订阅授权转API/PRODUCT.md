# PRODUCT.md — xAI 订阅授权转 API

## 摘要

新增一种「xAI 订阅」渠道类型：管理员在渠道编辑抽屉里完成一次 xAI 账号的设备码登录
（界面显示短码与验证网址，浏览器确认后自动拿到令牌），令牌存进渠道密钥，下游用标准的
OpenAI 兼容接口调用 Grok 模型，用量走 Grok 订阅而非按量付费的 API Key。访问令牌自动续期，
续期失败或退出登录时有明确的状态与错误指引；该渠道对下游默认免费（定价 0），用量日志照常记录。

## 行为

### 一、渠道类型与入口

1. 「添加渠道」的类型列表新增**「xAI 订阅」**，与既有的 48 号「xAI」（API Key）并列但相互独立：
   两种计费来源不同，列表与详情里都能区分，授权来的渠道带「账号登录」标识，呈现方式与既有的
   订阅类渠道（ChatGPT 订阅）保持一致。
2. 选中该类型后，接口地址固定为 `https://api.x.ai/v1`，只读展示、不可编辑——地址是订阅登录的
   一部分，不允许指向别的主机。
3. 该类型的密钥区域**不是自由文本框**：显示登录状态（未登录 / 登录中 / 已登录）与
   「登录 xAI 账号」按钮；已登录时显示账号标识（userinfo 或 ID 令牌里的邮箱）与脱敏状态，
   不显示令牌本身。
4. **未完成登录不能保存渠道**：该类型的密钥只能由登录流程产生，保存时没有有效登录则阻止保存
   并提示先完成登录。
5. 密钥区域同时提供一个次要入口「手动粘贴 OAuth JSON」（与既有订阅类渠道一致），供页面登录
   不可用时使用：粘贴的 JSON 必须包含 `access_token`；包含 `refresh_token` 时才能自动续期，
   缺少时允许保存但界面明确提示「无法自动续期，到期后需重新粘贴」；格式错误或缺少访问令牌时
   阻止保存并说明原因。粘贴成功后的渠道状态、续期、退出登录等行为与页面内登录完全一致。
6. 登录开始前，界面必须先展示风险说明（黄色警示区），内容至少包含：此登录借用 xAI 官方命令行
   工具的公开登录入口、不是 xAI 为本项目注册的应用；xAI 可能限制这种用法、账号有被限制的风险；
   有的订阅档位登录成功后仍不能调用（会提示 403），那时请改用 xAI 的 API Key。不点「继续登录」
   不发生任何网络请求。

### 二、设备码登录流程

7. 点「登录 xAI 账号」后，界面进入登录中状态并展示：**用户短码**（大号等宽字体、一眼可读）、
   **验证网址**（可点击）、**有效期倒计时**（分钟级）、**取消**按钮。
8. 界面提供「复制短码并打开验证页」按钮：短码写入剪贴板，同时新窗口打开验证网址；已复制给
   一次性提示，不弹阻塞对话框。
9. 等待确认期间，短码与验证网址始终保持可见可操作；界面明示「等待在浏览器里确认」，不自动
   跳转、不倒计时归零后静默失败。
10. **刷新页面或重新打开抽屉不丢登录进度**：轮询在服务端继续，界面重新挂载后恢复显示短码、
    验证网址与剩余有效期。
11. 登录成功后的界面反馈：成功提示、密钥区域切到已登录状态（见 3）、**自动拉取该账号可用的
    模型列表**并填入渠道的模型字段，管理员可手动刷新。
12. 登录失败时按原因给出可读文案与「重试」入口，至少覆盖：
    - 用户在浏览器里**拒绝**授权；
    - 短码**过期**（未在有效期内确认）；
    - 轮询**超时**；
    - **网络错误**（一时连不上 xAI）；
    - **账号没有可用订阅**（授权范围里没有该订阅接口的权限）；
    - **安全校验失败**（xAI 的发现文档签发方或端点主机不在预期范围，请求不会发出去）。
13. 同一时刻只允许一次登录：另一渠道正在登录时，「登录 xAI 账号」按钮禁用并说明原因。
14. 取消登录：停止轮询，回到未登录状态，不残留「登录中」标记，可立即重新发起。
15. 登录期间网关进程重启：登录态丢失，界面回到未登录，可重新发起（已确认的授权不受影响，
    重新登录即可）。

### 三、调用与模型

16. 该渠道的聊天请求打到 `https://api.x.ai/v1/responses`，请求头携带订阅访问令牌；下游使用
    `/v1/chat/completions` 或 `/v1/responses` 入口调用均正常，与既有 xAI 渠道的能力集一致。
17. 「获取模型」用订阅令牌拉取 xAI 的模型列表，行为与既有渠道一致（可重复拉取、可手动编辑）。
18. 渠道的**测试**按钮对该类型走 Responses 端点并允许流式，与既有订阅类渠道的测试方式一致。
19. 该渠道只承载 responses 聊天能力：用该渠道调用 xAI 的图片、视频等其他能力时给出明确的
    「该渠道不支持」错误，不静默失败、不假装成功。

### 四、令牌续期与失效（用户可见面）

20. 访问令牌临近过期时由网关自动续期，**对下游无感知**：不应出现因续期导致的请求失败。
21. 续期被服务端终局拒绝（授权已撤销、刷新令牌失效等）：渠道进入**「登录失效」**状态，
    在渠道列表与详情可见；此后该渠道的请求返回明确错误「xAI 登录已失效，请重新登录」，
    不表现为难以理解的 401、不无限重试。
22. 续期时遇到网络或服务端临时错误：不影响当前仍有效的令牌，后续继续尝试，不把渠道标记为失效。
23. 提供手动「刷新凭证」入口（与既有订阅类渠道一致）：点击立即续期，显示刷新结果
    （成功含过期时间，失败含原因）。
24. 保存渠道时若登录已失效：阻止保存并提示重新登录，不把失效令牌存下去。

### 五、退出登录

25. 退出登录只清除**本网关**的令牌：渠道本身、模型列表、既有配置全部保留，重新登录后即可恢复，
    不需要重建渠道。
26. 退出后该渠道立即可用性归零：请求返回「未登录」类错误，引导重新登录。
27. 界面提示：xAI 账号侧的授权需用户自行到 xAI 账号设置页断开（提供链接），网关的退出登录
    不会撤销账号侧的授权。
28. 同一个 xAI 账号可以同时在本网关和其他客户端（如手机端 Mika）登录，两边授权互不影响、
    互不可见，网关不独占账号。

### 六、计费与用量

29. 该渠道的模型**默认定价为 0**：下游调用不扣除配额（免费放行）；用量本身走 Grok 订阅，
    由 xAI 侧执行限额。
30. 用量日志照常记录：模型、token 数、渠道、时间落在既有日志与用量统计里，可在用量页看到
    订阅额度的消耗情况。
31. 上游返回 429（订阅速率上限）：按既有渠道的限速错误透出，错误信息可读；不把订阅限额
    伪装成网关错误。
32. 上游返回 403（订阅档位不能用该接口）：错误信息明确告知「订阅档位不能用这个接口，
    请改用 xAI 的 API Key」，不重试、不静默切换渠道后假装成功。

### 七、安全不变量

33. 访问令牌、刷新令牌**不出现在任何界面**（脱敏状态除外）、不进日志、不进诊断信息导出；
    用户短码不是机密，可以展示。
34. 所有发往 xAI 的地址（发现文档、设备码、令牌、用户信息、验证页）必须通过主机白名单校验，
    只认 `auth.x.ai` 与 `accounts.x.ai`；校验不通过时拒绝发起请求，并把失败归因为安全校验失败
    （见 12），绝不把令牌发往别的主机。
35. 会话的存储与既有渠道密钥同一机制（同一处、同样加密），不因是订阅授权而降低存储保护。
36. 登录借用的是 xAI 官方命令行工具的公开客户端标识，与项目内既有订阅类渠道同一模式；
    该标识写在前端可见的风险说明里，不隐瞒。

### 八、一致性与国际化

37. 所有新增文案走项目 i18n，**7 种语言**（zh、zh-TW、en、ja、fr、ru、vi）补齐，不出现
    硬编码中文。
38. 该类型在渠道列表、类型选择器、详情里的命名统一为「xAI 订阅」，与「xAI」（API Key）
    在界面上可明确区分，不混淆两种渠道。
