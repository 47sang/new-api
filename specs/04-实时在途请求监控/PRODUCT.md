# PRODUCT.md — 实时在途请求监控

## 摘要

在管理员用量分析页（`/dashboard/usage`）新增一块「在途请求」面板：通过服务端推送（SSE）实时展示
当前压在网关上的请求，**按模型 ID 分节**，每节节头显示 `(当前在途 - 峰值)`——峰值是该模型观测到的
最大并发水位（撞上游 429 时也会抬升），只增不减、重启归零。用于 429 出现时立刻判断是突发流量还是
某个客户端在堆积，以及给每个大模型摸出一条并发上限参考线。

## 行为

### 一、位置与可见性

1. 面板位于用量汇总卡（含「模型缓存占比」）**正下方**、活跃度热力图**上方**，是同一页面内的一个新
   卡片，不需要跳页。
2. 仅管理员（role ≥ 10）可见；非管理员访问页面时该卡片不渲染，接口返回原有未授权响应。
3. 面板不占用页面既有的时间范围 / 指标控件：在途数据与「最近 7 天 / Token / 消费」无关，切换这些
   控件不影响面板内容。

### 二、实时连接

4. 面板挂载后立即建立一条到网关的推送连接，服务端**每秒推送一次**全量快照，每 15 秒发送一次心跳。
5. 连接中断（网络波动、服务重启、页面休眠）时面板显示「连接中…」状态并**自动重连**，重连间隔逐步
   退避（1s → 2s → 4s，上限 30s）；恢复后状态消失。
6. 连续 45 秒收不到任何数据（含心跳）视为连接已死，主动断开并重连。
7. 组件卸载时关闭连接，不遗留请求。
8. 一期不做「暂停 / 冻结快照」按钮。

### 三、汇总与分组表格

9. 面板头部显示两个汇总数：**当前在途请求总数**、**在途请求的预计读取 token 合计**。
10. 主体是一张**按模型 ID 分节**的表格，节与节上下排列：每个模型一节，节头行显示
    「模型名 + `(当前在途 - 峰值)`」，节头下方是该模型在途请求的明细行。不同厂商 / 不同模型各占
    一节，可以纵向并排对比各自的并发水位。
11. **节头行的 `(当前在途 - 峰值)`**：
    - 当前在途 = 该模型当前处于在途状态的请求数；
    - 峰值 = 该模型**观测到的最大同时在途数**；每当该模型撞上一次**上游返回的 429**，也用当时的在途
      数取一次最大值；
    - 峰值**只增不减**，进程重启后归零（内存态，不持久化，也没有重置按钮）。
12. 尚未出现过在途、也没撞过 429 的模型不占节；**当前 0 在途但已有峰值的模型仍然占一节**，节头显示
    `(0-峰值)`，否则请求一停就看不到历史上限。
13. 节内请求行按开始时间排序，最新发起的排在明显位置（节内首行）。

### 四、在途请求明细行

14. 每一行展示：模型名、用户名、令牌名、**已进行时长**（秒级走动，如 `12s`）、
    **预计读取 token**（带「估算」标注）、渠道名、**状态标记**。
15. **状态标记**只有两种：`活跃` 与 `排队`——请求已发给上游算活跃；还在选路、预扣、重试退避的算排队。
16. 已进行时长每秒递增；请求结束后该行消失，节随之收缩；某模型在途归零但峰值保留时该节只剩节头行。
17. 预计读取 token 是 relay 侧的估算值，不追求精准；界面上必须带「估算」标注，避免被当成精确值。

### 五、空状态与加载

18. 完全没有在途请求、且没有任何模型撞过 429 时，表格区域显示空状态文案（如「当前没有进行中的请求」）。
19. 连接建立中（尚未收到第一帧）时表格区域显示加载骨架，不展示空白。
20. 连接失败且重连中时，表格区域保留最后一次快照并显示「连接中…」提示，不清空数据。

### 六、一致性与国际化

21. 在途数据是进程内内存实时态，与使用日志（落库态）不保证逐条对应；面板不承诺与日志一致。
22. 注册表是**进程内**的：多节点部署时只能看到当前节点，面板需有一处说明（如标题下的次要文案），
    避免误以为是全集群视图。
23. 所有文案走 i18n，七种语言补齐；时长与 token 数字复用项目既有格式化工具。
24. 表格在窄屏下可横向滚动或折叠次要列，不出现内容裁剪。
