# 意图：实时在途请求监控

> 作者：zhou。状态：草稿。
> 创建时间：2026-10-14
> 下游产物：[PRODUCT.md]（待生成）

## 问题

现在网关一旦返回 429，我完全看不到「当时到底有几个请求压在网关上」：只能事后翻使用日志逐条
复盘，既慢又看不出并发形状。缺一个实时视角——当前有哪些请求正在跑、各自处于什么阶段、已经
跑了多久、预计要吃多少输入 token，这样 429 一出现就能立刻判断是突发流量还是某个客户端在堆积。

## 预期成果

1. 用量分析页（`/dashboard/usage`）下方新增一块「在途请求」面板，服务端推送（SSE）实时刷新，
   不用手动刷新页面。
2. 面板头部给出汇总：当前在途请求数、在途请求的预计读取 token 合计。
3. **按模型 ID 分组的表格**（每个模型一节，节与节上下排列）：节头行显示
   「模型名 + `(当前在途 - 峰值)`」，节下面是该模型的在途请求行。不同厂商的模型各占一节，
   可以并排纵向对比各自的并发水位。
4. `(当前在途 - 峰值)` 是本功能的核心：**峰值只由上游 429 抬升**——每当某个模型撞上一次
   上游 429，就把峰值抬到「当时该模型的在途数」，只增不减，进程重启归零（内存态）。
   尚未撞过 429 的模型显示 `(0-0)`。
5. 每个在途请求一行：模型名、用户 / 令牌名、已进行时长（秒级走动）、预计读取 token、渠道，
   外加一个**「活跃 / 排队」标记**——请求已发给上游算活跃，还在选路 / 预扣 / 重试退避算排队。
6. 当前 0 在途但已有峰值的模型**仍然占一节**，显示 `(0-峰值)`，否则请求一停就看不到历史上限。
7. 请求结束后该行消失，列表随之收缩；完全没有在途、也没有任何模型撞过 429 时显示空状态。

## 受影响的用户和系统

- **用户角色**：管理员（role ≥ 10）。
- **涉及模块**：
  - 后端 `controller/relay.go` 的 `Relay()` 入口（请求开始时注册、结束时注销）、
    新增进程内在途注册表、新增管理员 SSE 接口
  - 前端 `web/src/features/dashboard/`（用量分析页新增面板 + SSE 订阅）
- **新增模块**：在途注册表（纯内存，不落库）、SSE 端点。

## 目标 / 非目标

**目标**

- 实时看到在途请求及其关键维度，用于 429 排队判断。
- 对 relay 主链路零可感知影响（无锁或细粒度锁、容量有界）。
- 请求异常中断（客户端断开、上游报错、panic）后注册项必须被清理，不能泄漏。

**非目标**

- 不做历史请求回放（已完成请求去看使用日志）。
- 不做跨节点汇总：注册表是进程内的，多节点部署只能看到当前节点（一期）。
- 不落库、不加持久化、不加新的数据表。
- 不做按用户/模型的聚合视图（本期只列行 + 两个汇总数）。

## 约束

- 仅管理员可见，接口必须做管理员鉴权；非管理员调用返回原有未授权响应。
- 与日志明细可能不一致：在途是内存实时态，日志是落库态，面板不承诺与日志逐条对应。
- **只统计上游返回的 429**：网关自身的限流（`middleware/model-rate-limit.go`）是按「用户分组 /
  全局」计的每分钟次数上限，不是按模型的并发上限，把它归到某个模型头上会归属模糊，因此不抬升
  模型峰值。
- 刷新方式按用户选择为 **SSE 推送**（项目内现有先例是轮询，本次是首次引入推送，需要处理
  断线重连与心跳；不设并发连接上限，本机单实例使用）。
- 预计读取 token 沿用 relay 侧既有口径（预扣费同源的估算值），不新造估算逻辑。
- 国际化：所有文案走 i18n，七种语言补齐。

## 已确认决策（2026-10-14）

| 议题 | 结论 |
| --- | --- |
| 在途定义 | 从进入 `Relay()` 到响应结束（含选路 / 预扣 / 重试退避） |
| 排队中的请求 | 算进在途；被限流挡下的属于 429 情况，见约束里的归属规则 |
| SSE 连接管理 | 做断线重连 + 心跳；不设单实例并发连接上限 |
| 暂停按钮 | 一期不做 |
| 预计读取 token | 用 relay 侧既有估算值，不追求精准 |
| 峰值规则 | 初值 0，**只由上游 429 抬升**到当时在途数，只增不减；重启归零（内存态） |
| 429 归属 | 只算上游 / 渠道返回的 429；网关侧分组限流 429 不抬升模型峰值 |
| 空闲模型 | 0 在途但已有峰值的模型仍占一节，显示 `(0-峰值)` |
| 排队边界 | 请求发给上游之前（选路 / 预扣 / 重试退避）都算排队 |
| 分组布局 | 一张表按模型分节，节头行带 `(当前在途 - 峰值)` |
| 峰值持久化 | 不持久化，进程重启即重置 |
